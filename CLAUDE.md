# SeatSense

Library seat finder for our Enterprising Web Applications (Java) course project.

Read docs/PROJECT.md before any work. Then read docs/api.md once it exists.

## Rules
- Work only in modules owned by the person you are helping (docs/PROJECT.md, Section 13). If a change is needed in the other person's module, stop and say so.
- Never change an existing Flyway migration. Add a new one. Shefali uses odd versions (V1, V3, ...), teammate uses even (V2, V4, ...).
- Every new backend behaviour comes with a test.
- All time goes through the injectable clock.
- Commit messages: short, imperative, written as the person committing. No AI attribution, no "Co-Authored-By" lines, no "Generated with" lines in commits, PRs, issues or the README.
- Never commit secrets (.env, passwords, keys). Use .env.example.
- Follow the design rules in docs/PROJECT.md Section 17 for any UI or copy.
- Sample data must be labelled as sample data. Never invent statistics.
